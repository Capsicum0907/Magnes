# 仕組み

[English](how-it-works.md) | 日本語

以前はソースコードに書いていた説明です。コードを短く保ち、理由の置き場所を一箇所にするため、ここへ移しました。

## 走査

この Mod がすることは `Magnetism.sweep(player)` がすべてです。イベントハンドラーの中身にせず普通のメソッドにしているのは、
テストが実際のティックを起こさなくても、走査を1回呼んで結果を確かめられるようにするためです。

呼び出し元は `PlayerTickEvent.Post` です。ティックの後に呼ぶので、プレイヤーがそのティックを終えた位置で判定されます。
間隔はサーバーのティック数ではなくプレイヤー自身の `tickCount` で数えます。こうするとプレイヤーごとに走査するティックがずれ、
全員が同じティックに集中しません。

クライアント側、死亡中のプレイヤー、スペクテイターモード、全体のスイッチがオフのとき、プレイヤーに磁力がないときは何もしません。

## 誰に磁力があるか

次の順に調べます。

1. `magnet.needed` がオフなら、全員にある。
2. どちらかの手に、オンの磁石がある。
3. Curios が入っていれば、Curios のスロットにオンの磁石がある。
4. `magnet.mustBeHeld` がオンなら、ここで打ち切る。
5. メインインベントリのどこかに、オンの磁石がある。

身に着けた磁石は、鞄の中の磁石ではなく「手に持った磁石」として数えます。身に着けるのは意図して装備する行為であり、
`mustBeHeld` が求めているのはまさにそれです。そう扱わないと、この設定をオンにした人にとってスロットが役に立たなくなります。

磁石が必要なことを強く書いているのは、初めて遊んだときにこの Mod が壊れているように見えたからです。
「アイテムがプレイヤーに寄ってくる」と名乗り、`enabled` という全体のスイッチまで用意しておきながら、
誰にも知らされていないアイテムを待って何もしませんでした。`needed = false` は、その読み方を本当にしたい人のための設定です。

## 手を出さないもの

拾えるまでの待ち時間がまだ残っているアイテムは飛ばします。この待ち時間があるからこそ、そもそもアイテムを捨てられます。
これを無視すると、磁石は投げた瞬間にすべて取り返してしまいます。死んだばかりの他のプレイヤーのドロップに手が届かないのも、
この待ち時間のおかげです。

## 拾う処理

拾う処理を自前では書いていません。アイテムも経験値オーブも、`playerTouch` を通じて自分をプレイヤーに渡す方法を既に持っています。
そこでは、拾えるまでの待ち時間、アイテムの持ち主、効果音、進捗、他の Mod が聞いている拾得イベント、
オーブなら経験値より先に修繕を適用すること、がすべて扱われます。

- `TAKEN` はその場で `playerTouch` を呼びます。
- `DRAWN` はプレイヤーの目の位置へ向けて `drawnSpeed` の速度を与え、あとは通常の拾得に任せます。
  既にプレイヤーと重なっているものは直接触れさせます。そこまで近いと、向きを求めても意味のない値になるためです。

オーブはゲーム本来の速さ、つまり2ティックに1個のペースで吸収されます。

## スイッチ

オンかオフかはデータコンポーネント `magnes:active` で持ちます。無ければオン扱いなので、一度も触っていない磁石はそのまま効き、
コンポーネントも持ちません。

状態は絵柄で示します。オンはカラー、オフはグレーです。エンチャントの光沢は赤と青のアイテムの上ではほとんど見えないので使いません。
基本のモデルをオフ側、上書きをオン側にしているのは、モデルの上書きが「条件に合ったときだけ基本のモデルを置き換える」仕組みだからです。
上書きが読む数値はアイテムプロパティ `magnes:active` で、これはクライアント側で登録します。モデルは、その数値をどこから取るかを
自分では指定できないためです。

右クリックでコンポーネントを反転し、レバーの音を鳴らします。音程はオンで高く、オフで低くします。
ツールチップにはサーバーの設定している届く距離を出しますが、設定が読み込まれているときだけです。
同じツールチップはタイトル画面でも描かれることがあり、そこで設定を読むと例外になるためです。

## 設定はその場で読む

設定はサーバー設定です。落ちているアイテムの位置はワールドの状態で、ワールドの状態を決めるのはサーバーだけだからです。
クライアントはホストの値を受け取ります。どの値も使うそのティックに読みます。道具の採掘範囲のように、
アイテム登録時にデータコンポーネントへ焼き込まれる値とは違い、これらを設定にできるのはそのためです。

各項目の働きは [config.ja.md](config.ja.md) にあります。

## Curios

Curios は任意です。連携は「オンの磁石を身に着けているか」という1つの問いだけで、`curios/Worn` で尋ねます。
Mod の他の場所で Curios のクラスを名指しすることはありません。

これを守る判定は `Worn` ではなく `Mods` に置きます。静的メソッドを呼ぶと、そのメソッドを持つクラスが初期化されます。
守る対象の隣に判定を置くと、避けたかったクラスそのものを読み込んでしまい、Mod は構築中に `NoClassDefFoundError` で落ちます。
使う側はすべて短絡評価にしてあり、答えが「入っている」のときだけ Curios 側に進みます。

残りは生成される2種類のデータファイルが受け持ち、それぞれ別の問いに答えます。

- `data/magnes/curios/entities/player.json` は、プレイヤーがそもそも charm スロットを持てるか。
  Curios はスロットの定義を同梱していますが、誰にも割り当てません。これが無いと Curios のボタンは出るのに、開いても何もありません。
  初めて遊んだときがまさにその状態でした。
- `data/curios/tags/item/charm.json`（と `curio.json`）は、磁石がそこに入るか。どのスロットも
  `"validators": ["curios:tag"]` で宣言されていて、`curios:<スロット名>` のタグを見ます。

要求するスロットは `charm` だけです。磁石には何でも入る `curio` スロットのタグも付けてあるので、他の Mod が既にそのスロットを
追加している環境ではそこにも入ります。ただ、アイテム1つのために全プレイヤーへスロットを2つ足すのは場所の取りすぎです。
タグファイルは Curios の有無にかかわらず書き出します。誰も宣言していないスロットを指すタグは、誰にも読まれないだけで害はありません。

## 生成されるデータ

`src/generated/resources` の中身はすべて `data/MagnesDataGen` と `data/TestStructures` が作り、手では書きません。
レシピは磁石の形そのまま、2本の腕とそれをつなぐ棒の並びです。

データ生成は、生成器ごとのハッシュを `.cache` に残します。これはこのリポジトリの作業記録なので、`build.gradle` で jar から除いています。

## テスト

`gradlew runGameTestServer` で実行します。

うち3件は「取らない」ことの確認です（届く距離の外、拾えるまでの待ち時間中、スイッチがオフ）。
取りすぎる磁石は、取り足りない磁石より悪いからです。

- テストの舞台は `TestStructures` が NBT として書き出す 20×5×20 の床です。データバージョンはゲームから取るので、古くなって
  ずれることがありません。この Mod は距離が主題なので、広く取っています。空気を含めて全セルを列挙するので、
  前のテストが残したものが次のテストに持ち越されません。
- `leavesItemsBeyondReach` は届く距離を仮定せず、明示的に設定します。以前、届く距離を32に上げた設定で実行して落ちたことがあります。
- `theTickReachesTheSweep` は本物のティックイベントを送ります。他のテストは `sweep` を直接呼ぶので、ゲームと走査の間にある
  リスナーを誰も確かめていませんでした。どこにもつながっていない Mod でも、「何をするはずか」のテストには全部通ってしまいます。
- `aMagnetCanBeWorn` は Curios のタグを確かめます。装備できるかどうかはデータファイルの問題で、ディレクトリ名を1文字間違えると、
  コードは正しく動いたまま、何も入らないスロットを相手にすることになります。このテストは Curios なしで走ります。
  どの Mod も持たない名前空間のタグファイルが何も壊さないことも、同時に示しています。
- テストは `makeMockServerPlayerInLevel` を使っています。これは削除予定で、代わりの手段が示されていません。
  経験値オーブは `ServerPlayer` にしか自分を渡さないので、経験値側をテストする方法が他にありません。
  これが削除されたときは、ここを考え直す必要があります。
